# About

I'm an engineer who prefers a number to an adjective. Most of what I have built has been software
other people run: systems that have to keep working when nobody is watching, where "it works on my
machine" is not a finished sentence.

The last year has been about the other half — the AI half — built in public rather than described in
a cover letter. A card game that four people play over a tunnel. A Python port of the same game with
a paired benchmark that measures the existing opponent before any model is trained. Next: retrieval
with an eval harness that could embarrass me, and an agent that survives failure rather than
performing on a happy path.

## How I work

- **Measure before claiming.** Every project here has a test suite and a number that reproduces from
  a seed. Where the first measurement was wrong, the mistake is written down next to the fix.
- **Prefer the boring part.** A benchmark control row, a watchdog that restarts a tunnel, a push that
  refuses to run on a red suite — the unglamorous pieces are what make the rest trustworthy.
- **Build the thing, not the demo.** The card game is played with my family on a Tuesday; the tunnel
  survives the machine rebooting because of a script that checks it every 45 seconds.
